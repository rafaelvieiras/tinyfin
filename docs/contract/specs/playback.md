# Playback: track selection and burned-in subtitles in PlaybackInfo and HLS

What a client sees when it asks for a particular audio track or a subtitle that has to be rendered into the picture: what PlaybackInfo says (direct play or not, the `TranscodingUrl` and the parameters in it), and what the HLS routes of that URL answer. Probed on the 12.2 reference with online metadata off.

Scenarios: [`../scenarios/playback.json`](../scenarios/playback.json), [`../scenarios/playback2.json`](../scenarios/playback2.json), [`../scenarios/playback4.json`](../scenarios/playback4.json) (the offer), [`../scenarios/playback5.json`](../scenarios/playback5.json) (segment plan, seek, repeated names), [`../scenarios/playback6.json`](../scenarios/playback6.json) (stream bit rates, members, container names). Fixture state: [`../fixtures.json`](../fixtures.json), media from `scripts/conformance-media.sh` (lazy library `AvTrack`; library `Strm` holds a `.strm` whose address `scripts/conformance-strm-serve.sh <media-root>` serves, it must be running for `playback.offer.strm-http`).

## Fixture facts this spec relies on

* `Av Multi (2400)` is a Matroska file, H.264 video (index 0), AAC audio `eng` (1, default), MP3 audio `por` (2), embedded SubRip `eng` (3, default) and ASS `por` (4).
* The scenarios use a profile whose only direct play entry is `mkv` / `h264` / `aac`, with a `ts` / `h264` / `aac` HLS transcoding profile; the `SubtitleProfiles` vary per step.

## <a id="audio"></a>Audio track

- **playback.audio.R1** `AudioStreamIndex` (query or body) selects the audio track of the media source named by `MediaSourceId`: the source's `DefaultAudioStreamIndex` is that index. Without the track, `DefaultAudioStreamIndex` is the default audio track.
- **playback.audio.R2** When the selected track is one the profile can direct play, the answer is the direct play one (`SupportsDirectPlay` true, no `TranscodingUrl`). When it is not, `SupportsDirectPlay` is false, `SupportsTranscoding` true, `TranscodingSubProtocol` `hls`, `TranscodingContainer` the transcoding profile's container, and `TranscodingUrl` is the `master.m3u8` of the video with `AudioStreamIndex=<n>` and `TranscodeReasons` naming `AudioCodecNotSupported`.
- **playback.audio.R3** The selection is ignored when `MediaSourceId` is missing, when the index is not an audio stream of the source and when it is past the streams: `DefaultAudioStreamIndex` stays the default track.
- **playback.audio.R4** The same fields in the POSTed body have the same effect.
- **playback.hls.R1** `GET` of the `TranscodingUrl` answers `200` `application/vnd.apple.mpegurl`: `#EXTM3U`, an `#EXT-X-STREAM-INF` entry and the `main.m3u8` it points at, whose query keeps `AudioStreamIndex`, `SubtitleStreamIndex` and `SubtitleMethod` of the URL. A change of track in a play session is a new URL, hence a new transcode.
- **playback.hls.R2** The master playlist (`master.m3u8`, `MediaSourceId` required) has one variant: `#EXT-X-STREAM-INF:BANDWIDTH=<n>,AVERAGE-BANDWIDTH=<n>,VIDEO-RANGE=SDR,CODECS="<video>,<audio>",RESOLUTION=<w>x<h>,FRAME-RATE=<fps>` (plus `,SUBTITLES="subs"` when the group is present) and the link `main.m3u8?<query>`. The query is the request's, parameters in order, repeated names (any letter case) gathered at the first one (every route of the HLS family reads a repeated name as its first value, `AudioBitrate=64000&audiobitrate=32000` is 64000), with `AudioCodec` rewritten to what is played (`copy` when the source codec is on the list and the channel and bit rate limits allow, else the first listed codec; appended when absent); `VideoCodec` stays as sent. `BANDWIDTH` is `VideoBitrate` (0 when absent) plus the audio rate: the smaller of `AudioBitrate` and the rate of the channels left after `TranscodingMaxAudioChannels`/`MaxAudioChannels`/`AudioChannels` (128000 for one, 256000 for two, three and four, 640000 for six and more, and 768000 for exactly five when the source itself has five (no LFE); when the first codec listed is `mp3` the channels count at most two, even if another codec is played). A `flac` audio rate is the bit rate of the source's own sound (limits and `AudioBitrate` do not change it), and a flac track that has to be re-encoded to flac writes no audio entry in `CODECS`. The picture is copied when its codec is on the list and the source provably fits `VideoBitrate`, `MaxWidth`/`Width`, `MaxHeight`/`Height` and `MaxFramerate` (a source whose bit rate is unknown never fits a `VideoBitrate`). `CODECS`: a copied picture writes its own profile and level (`avc1.64001F`); an encoded h264 picture the first known profile of `h264-profile` (`baseline` `42E0`, `constrainedbaseline` `4240` the default, `main` `4D40`, `high` `6400`) and `h264-level` (default 41, at most 51) as `avc1.<profile><level hex>`; hevc `hvc1.<1|2 for main10>.4.L<hevc-level, default 120, at most 150>.B0`; av1 `av01.0.15M.08`; vp9 and unknown codecs write no video entry. Audio: `mp4a.40.2` (aac), `mp4a.40.34` (mp3), `ac-3`, `ec-3`, `Opus`, `fLaC`, none for others. `RESOLUTION` is the source's, narrowed by `MaxWidth`/`Width` only (height from the aspect ratio, ties to even; the height limits do nothing); an encoded picture without any `VideoBitrate` is also limited to width 416. `FRAME-RATE` is `MaxFramerate` when sent, else the source's (`23.976`). A list of video codecs picks `h264` when present, else `vp9`, else the first.
- **playback.hls.R3** The media playlist (`main.m3u8`, any `MediaSourceId` or none) is `#EXTM3U`, `#EXT-X-PLAYLIST-TYPE:VOD`, `#EXT-X-VERSION:3`, `#EXT-X-TARGETDURATION:<ceil of the longest segment>`, `#EXT-X-MEDIA-SEQUENCE:0`, then per segment `#EXTINF:<seconds %.6f>, nodesc` and `hls1/main/<n>.<container>?<the request's query>&runtimeTicks=<start>&actualSegmentLengthTicks=<length>`, then `#EXT-X-ENDLIST`. An encoded picture is cut on a grid of `SegmentLength` seconds (default 6), the last segment shorter. A copied picture in a Matroska/WebM file is cut at its key frames: the i-th segment (from 0) ends at the first key frame, by presentation time, at or after `(i+1) * SegmentLength` seconds that follows the previous cut (so a gap of 20 s between key frames makes a 20 s segment, and the key frames that follow it each close a short one until the grid is caught up); the last runs to the end of the run time. Every other container lists the grid even when the picture is copied (`playback.hls.keyframe-plan`).
- **playback.hls.R4** `GET /Videos/{id}/hls1/{playlistId}/{n}.{container}` answers `video/mp2t` for `ts`. `runtimeTicks` and `actualSegmentLengthTicks` are required (`400` problem document naming the missing ones, `The <name> field is required.`), `n` must be a number (`segmentId`, `The value 'x' is not valid.`).
- **playback.hls.R5** `StartTimeTicks` is accepted and carried in the links of the master and media playlists without changing them (the playlist always covers the whole run time). A segment request with a `StartTimeTicks` other than 0 (or empty) is `400` `text/plain` `Error processing request.`; 0 is accepted.
- **playback.hls.R8** A segment request starts the transcode at its own position: `runtimeTicks` is where in the file the segment starts and `n` only the number it is served under (neither is checked against the playlist). A transcode is not begun by the playlists, and one that is running serves the next segments; asking for one further on, or an earlier one, starts a new one there. The segment timestamps are the source's plus 10 s (the segment that opens at `runtimeTicks` of 30 s of the file starts at 40 s; the first one at 10 s), whatever the position. A `runtimeTicks` past the end of the run time answers `200` with the last seconds of the file (the last key frame segment of a copied picture), not a failure (`playback.hls.segment-seek`).
- **playback.hls.R6** Failures of `master.m3u8`/`main.m3u8`: an item id that is not a GUID `400` problem (`itemId`); `segmentLength`, `startTimeTicks`, `audioStreamIndex` or `subtitleStreamIndex` that is not a number `400` problem (`The value 'abc' is not valid.`); no `MediaSourceId` on the master `400` problem (`mediaSourceId`); the zero item id or a media source that is not one of the item's `400` `text/plain` `Error processing request.`; an unknown item `404` (same body); a `MediaSourceId` that is not a GUID `500` (same body). A source that would be direct played answers like any other: both streams copied.
- **playback.hls.R7** With `SubtitleMethod=Hls` the master lists every text subtitle track of the source (embedded and external, in stream order; bitmap tracks never) before the variant: `#EXT-X-MEDIA:TYPE=SUBTITLES,GROUP-ID="subs",NAME="<display title>",DEFAULT=<YES for the track SubtitleStreamIndex names>,FORCED=<YES for a forced track>,AUTOSELECT=YES,URI="<itemId>/Subtitles/<index>/subtitles.m3u8?SegmentLength=30&ApiKey=<token>",LANGUAGE="<iso code>"` (`LANGUAGE` left out without one). The relative URI resolves, from `/videos/{id}/master.m3u8`, to `/videos/{id}/{id}/Subtitles/{index}/subtitles.m3u8` (`subtitles.playlist.R1`). Any other method writes no group.

## <a id="subtitle"></a>Burned-in subtitles

- **playback.subtitle.R1** A request with a device profile whose delivery for the selected subtitle (the requested `SubtitleStreamIndex`, else the default one, subtitles.default.R1) is `Encode` is not direct played: `SupportsDirectPlay` and `SupportsDirectStream` false, `SupportsTranscoding` true, and the `TranscodingUrl` carries `SubtitleStreamIndex=<n>`, `SubtitleMethod=Encode`, `AudioStreamIndex=<default or selected>` and `TranscodeReasons` naming `SubtitleCodecNotSupported` (after `AudioCodecNotSupported` when both apply, comma separated).
- **playback.subtitle.R2** `SubtitleStreamIndex=-1` is no subtitle: it is reported as `DefaultSubtitleStreamIndex` and nothing is burned in, even when the default track would be.
- **playback.subtitle.R3** A selected subtitle delivered by `External` or `Embed` does not make the answer a transcode, and the `TranscodingUrl` (when there is one for another reason) has no `SubtitleMethod`.
- **playback.subtitle.R4** When the source is transcoded for another reason (an audio track the profile cannot take), an embedded track whose delivery was `Embed` becomes `Encode` and the URL asks for it (`SubtitleMethod=Encode`, `SubtitleStreamIndex`). A `SubtitleStreamIndex` that names no stream is reported as sent in `DefaultSubtitleStreamIndex` and has no other effect.
- **playback.subtitle.R5** A delivery of `Hls` for the selected track also ends direct play, with `SubtitleMethod=Hls`, `SubtitleStreamIndex` and `SubtitleCodecNotSupported`.

## <a id="offer"></a>The offer: direct play or transcode

What `POST /Items/{id}/PlaybackInfo` says about a video, from the device profile. Probed with a matrix of profiles (hls and http transcoding entries) against mp4, mkv, avi and hevc files, plus multi-audio and `.strm` sources.

- **playback.offer.R1** A source the profile does not play as it is is never offered as direct stream: `SupportsDirectPlay` and `SupportsDirectStream` false, `SupportsTranscoding` true, also when only the container does not fit (codecs the profile takes) or only an audio track does not. `TranscodeReasons` lists what the profile cannot take (`ContainerNotSupported` alone for a container-only mismatch). The URL names the transcoding entry's codecs (`VideoCodec=h264`, never `copy`); what the transcode copies is decided when it runs (a codec the source already has is copied).
- **playback.offer.R2** The transcoding entry is the first `Video` entry whose `Context` is not `Static`. Its `Protocol` (case-insensitive) `hls` gives `TranscodingSubProtocol` `hls`, `TranscodingContainer` the entry's container and `TranscodingUrl` `/videos/{id}/master.m3u8?...` (with `SegmentContainer`); anything else, a missing protocol included, gives `TranscodingSubProtocol` `http`, `TranscodingContainer` the entry's container and `/videos/{id}/stream.<container>?...` (no `SegmentContainer`).
- **playback.offer.R3** A request without a `DeviceProfile` states no limit: direct play (`SupportsDirectPlay`, `SupportsDirectStream`, `SupportsTranscoding` true, no `TranscodingUrl`) for any container and codec, an audio track selection included. (The policy flags of `policy.md#playback` still apply.)
- **playback.offer.R4** `.strm` files holding an address are offered through the profile like a file with the container and codecs the address holds (probed when first played): direct play when the profile takes them (`Protocol` `Http`, `IsRemote` true, `Path` the address, `Container` the container name, `Bitrate` the probed bit rate of the address), else the transcode offer, whose input is the address and whose `Container` stays the source's (the probe's format name, `mov,mp4,m4a,3gp,3g2,mj2` for mp4, unless the profile's direct play entries list one of its names). A `.strm` with a local path, an empty one or an address that cannot be probed is offered as it is (R12 for a user who must have remote sources transcoded).
- **playback.offer.R5** The members of the `TranscodingUrl` and their order: `DeviceId`, `MediaSourceId`, `VideoCodec` (the entry's list, commas kept), `AudioCodec` (the source's codec when the entry lists it, else the entry's list), `AudioStreamIndex`, `SubtitleStreamIndex` (when a subtitle is burned in or delivered through the playlist), `VideoBitrate` (the bit rate ceiling minus the audio rate), `AudioBitrate` (the track's, else 192000), `AudioSampleRate` (only when the audio codec is kept), `MaxFramerate`, `SegmentContainer`, `SegmentLength`, `MinSegments` (hls entries), `PlaySessionId`, `ApiKey`, `TranscodingMaxAudioChannels`, `EnableSubtitlesInManifest`, `EnableMpegtsM2TsMode`, `EstimateContentLength` (`True` when the entry sets it), `TranscodeSeekInfo` (`Bytes` only), `CopyTimestamps` (the entry's, `True` when set), `RequireAvc=false`, `EnableAudioVbrEncoding` (the entry's, `true` when it does not say), `Tag`, `SubtitleMethod`, then `<videocodec>-level`, `-videobitdepth`, `-profile`, `-audiochannels` (the last when the audio codec is kept) of the source, `<audiocodec>-profile` and `-audiochannels` (a `VideoAudio` codec profile's `AudioChannels` limit) when the audio codec is kept, `TranscodeReasons`, and last `allowVideoStreamCopy=false` / `allowAudioStreamCopy=false` (see R7). The path is lower case with the dashed id. Values that vary (`PlaySessionId`, `Tag`, `ApiKey`, `DeviceId`) are only checked for presence.
- **playback.offer.R7** A request that forbids copying (`AllowVideoStreamCopy` / `AllowAudioStreamCopy` false, in the body, else in the query) ends the `TranscodingUrl` with `allowVideoStreamCopy=false` and/or `allowAudioStreamCopy=false` (video first); true or absent writes nothing. `BreakOnNonKeyFrames` of the entry is never written to the URL (probed with hls, http, every container and codec combination).
- **playback.offer.R8** A transcoded video source keeps the `Container` of the source (not the transcoding entry's) and every media source carries `MediaAttachments` `[]`, `Formats` `[]`, `RequiredHttpHeaders` `{}` and `UseMostCompatibleTranscodingProfile` false.
- **playback.offer.R9** A stream's `BitRate` is what the container states; failing that, for a Matroska stream the muxer's statistics tags: `BPS`, else `NUMBER_OF_BYTES` * 8 / the stream's `DURATION` tag (truncated); a tag that is not a positive number is ignored and tag names are case-insensitive. A track with neither gets, for an audio codec the reference knows, an estimate from the codec and the channel count: `aac` 192000 (up to 2 channels) or 320000 (more), `flac` and `alac` 480000 per channel, `opus` 128000, `vorbis` 160000, `truehd` 700000 per channel (probed on 1 to 8 channels where the build could encode them); other codecs (`tta`, `wavpack`) and every video track get none. The same values are in the item's `MediaStreams`.
- **playback.offer.R10** Every stream of a media source carries `AudioSpatialFormat` `None`, `VideoRange` and `VideoRangeType` (`Unknown` for anything but video). A video stream also carries `BitDepth` (from the pixel format), `IsAnamorphic` (a sample aspect ratio other than 1:1; `AspectRatio` is then the display ratio, `16:9` for 320x240 with 4:3 samples), `AverageFrameRate`, `RealFrameRate` and `ReferenceFrameRate`, `VideoRange` `SDR`/`HDR` with `VideoRangeType` `SDR`, `HDR10` (`smpte2084`) or `HLG` (`arib-std-b67`), `ColorTransfer`, `ColorPrimaries` and `ColorSpace` when the file declares them, and for H.264 `IsAVC` true and `NalLengthSize` `"4"` (neither for HEVC). `CodecTag` is the container's tag (`avc1`, `mp4a`) when it has one. An audio stream carries `TimeBase`, `LocalizedDefault`, `LocalizedExternal`, `LocalizedOriginal` and, when it has a language, `LocalizedLanguage` (`Undetermined` for `und`); a lossless one `BitDepth`. An address (`.strm`) lists no `RefFrames`.
- **playback.offer.R11** The `Container` of an MP4-family file (`mp4`, `m4v`, `mov`) or address is the format name `mov,mp4,m4a,3gp,3g2,mj2` (also without a profile); a profile that lists any of its names in a `Video` direct play entry (`mov`, `mp4`, ...) gets that name and plays it directly. A Matroska address is always `mkv`: `webm` and `matroska` in the profile name no direct play (`ContainerNotSupported`) and the container stays `mkv`.
- **playback.offer.R12** A user with `ForceRemoteSourceTranscoding` who states a profile is never offered a `.strm` file whose content cannot be probed (an unreachable address, a local path, an empty file) as it is: `SupportsDirectPlay` and `SupportsDirectStream` false, `Container` `strm`, the profile's transcoding entry as the offer (`hls` or `http`) with no stream parameters (`AudioBitrate=192000`, no `AudioStreamIndex`, no `MaxFramerate`), `TranscodeReasons` `ContainerNotSupported` (unless a `Video` entry lists `strm`) and `VideoCodecNotSupported`, and `allowVideoStreamCopy=false&allowAudioStreamCopy=false` for an address (not for a local path or an empty file). Without a profile, or for a user without the flag, the file is offered as it is (R4).
- **playback.offer.R13** `VideoRange` and `VideoRangeType` of a video stream come from the color transfer and the Dolby Vision configuration record (stream side data) together. Without a record: `smpte2084` is `HDR`/`HDR10` (`HDR10Plus` when the first frame carries dynamic HDR10+ metadata), `arib-std-b67` is `HDR`/`HLG`, anything else `SDR`/`SDR`; a Dolby Vision codec tag (`dvh1`, `dvhe`) with no record is `SDR`. With a record the profile and the base layer signal compatibility id decide: profile 5 is `DOVI`; 7 is `DOVIWithEL` (`DOVIWithELHDR10Plus` with HDR10+); 8 (and 10) with id 1 is `DOVIWithHDR10` (`DOVIWithHDR10Plus`) when the transfer is PQ, with id 2 `SDR`/`DOVIWithSDR`, with id 4 `DOVIWithHLG` when the transfer is HLG, and `DOVIInvalid` when the transfer does not agree or the id is 0 (profile 10 with id 0 is `DOVI`) or 6; any other profile counts as no record. The stream also carries `DvVersionMajor`, `DvVersionMinor`, `DvProfile`, `DvLevel`, `RpuPresentFlag`, `ElPresentFlag`, `BlPresentFlag` and `DvBlSignalCompatibilityId` (all absent without a record), `VideoDoViTitle` ("Dolby Vision Profile 8.1 (HDR10)": the compatibility id follows the profile when not 0, with its name for 1 HDR10, 2 SDR, 4 HLG, 6 HDR10) and a `DisplayTitle` that names it in place of the range label. `Hdr10PlusPresentFlag` is true only for the dynamic metadata of the first frame.
- **playback.offer.R14** `opus` above 2 channels and `vorbis` above 2 channels are estimated like the reference (R9): `opus` 128000 for 1 and 2 channels and 256000 from 3 to 8; `vorbis` 160000 up to 2 channels and 320000 above. Codecs the table does not cover (`ac3`, `eac3`, `dts`, `truehd`, `mp3`, `pcm`, ...) use the rate ffprobe reports, and the ones ffprobe cannot report get none.
- **playback.offer.R15** The `CodecProfile` entries of type `Video` whose `Codec` (when set) lists the video codec, whose `Container` (when set) lists the source container and whose `ApplyConditions` hold are evaluated against the video stream: `Equals`, `NotEquals`, `EqualsAny` (values separated by `|`), `LessThanEqual` and `GreaterThanEqual`, for `Width`, `Height`, `VideoBitDepth`, `VideoRangeType`, `VideoProfile`, `VideoLevel`, `RefFrames`, `VideoFramerate`, `VideoBitrate`, `VideoCodecTag` and `IsInterlaced`. A property the stream has no value for passes unless the condition is required. A condition that fails rules out direct play, remux and direct stream: the source is transcoded.
- **playback.offer.R16** The reasons of a transcode are the container, video codec and audio codec reasons of the direct play entries, then one reason per failed condition (without repeating one): `VideoResolutionNotSupported` (`Width`, `Height`), `VideoBitDepthNotSupported`, `VideoRangeTypeNotSupported`, `VideoProfileNotSupported`, `VideoLevelNotSupported`, `RefFramesNotSupported`, `VideoFramerateNotSupported`, `VideoBitrateNotSupported`, `VideoCodecTagNotSupported`, `InterlacedVideoNotSupported`.
- **playback.offer.R17** The `Container` of a video source in `PlaybackInfo` is named after the probed format, not the extension: Matroska `mkv`; WebM `mkv,webm` (the one of the two a `Video` direct play entry lists, which then plays directly); MPEG-TS and M2TS `ts`; ASF and WMV `asf`; MPEG program streams (`mpg`, `mpeg`) `mpeg`; Ogg video `ogg`; the MP4 family of R11 (`3gp` and `3g2` included) `mov,mp4,m4a,3gp,3g2,mj2` unless a direct play entry lists one of its names.
- **playback.offer.R18** When no audio stream is flagged default, the audio codec of the source does not restrict direct play (an entry listing only `ac3` plays a file whose only track is `aac`), and every transcode reason list names `AudioCodecNotSupported`.
- **playback.offer.R6** `GET` of an `http` offer (and of any `Videos/{id}/stream` request that carries `TranscodeReasons` and no `Static=true`) answers `200` with the source transcoded as one progressive stream in the URL's container (`video/mp4`, `video/x-matroska`, ...), no range support.
- Every video media source carries `Bitrate`, the rate of the file (`playback.offer.R5` scenario).

## Known differences

Observed on the reference and deliberately not reproduced (not asserted by a scenario that runs against both):

* **Offer values.** `AudioBitrate`, `MaxFramerate`, `<codec>-level` and `AudioSampleRate` come from what the scanner probed. Items scanned before the scanner kept the stream bit rate and frame rate are probed again by the next incremental scan (the scan signature records a probe version, `probeVersion`), so the member is missing only until that scan has run.
* **Playlist shape.** After a start in the middle of the file the reference cuts a copied picture by running the key frame rule again from there (its segments then differ from its own playlist: a start at a key frame two seconds before the next one gives one long segment); Tinyfin keeps cutting at the playlist's plan, so the segments follow the playlist. The timestamps of an mp4 copy are the file's (the reference shows them about 23 ms later), those of an encoded segment start within a frame of the same time. A copied picture's key frames are read with `ffprobe` (every packet header of the file, cached in memory and under the transcode work directory by path, size and modification time), so the first playlist of a large Matroska file waits for that scan. A segment past the end is the last 5 seconds of the file (the reference gives the last segment of its plan, within a second). A request asking only for a later position than the transcode in progress (more than 3 segments past what ffmpeg has written) restarts it; the reference's threshold is not observable.
* **Unknown stream bit rates.** Reproduced for the offer and the stream listings (R9); the codecs the estimate table does not cover (an audio codec the build could not encode, or whose estimate depends on a property not probed, such as `pcm` with an odd sample size) get none here, and a Matroska file whose tags lack `DURATION` falls back to the container's duration. The audio rates for `flac` (the source's own bit rate) and for 3 to 5 channels follow the reference (R8).
* **Reason lists with conditions.** For an HEVC source whose `CodecProfile` condition fails the reference also names `VideoCodecNotSupported` (and `AudioCodecNotSupported`, R18) before the condition's reason, although the direct play entry lists `hevc`; for H.264 it does not. The cause is not isolated, so Tinyfin names the condition's reason only (the scenario asserts that reason, not the whole list). Likewise a WebM source against a profile that names no Matroska name lists `VideoCodecNotSupported` for a codec the profile lists.
* **Rendering.** The burn-in is `libass` through ffmpeg's `subtitles` filter for text tracks (embedded or sidecar files, rendered at the source resolution before the scale) and the `overlay` filter for bitmap tracks (PGS, DVD, DVB). Text uses fontconfig's system fonts, or `-fonts-dir` / `TINYFIN_FONTS_DIR` when set; the reference's server-wide fallback font setting is not used. The rendering is checked by Go tests with a real ffmpeg (text and, in `TestBitmapBurnIn_RealFFmpeg`, PGS and DVD pictures; see `bitmap.burnin.R1`), not by a scenario.
